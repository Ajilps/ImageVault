1. System Overview & Architecture
A Progressive Web Application (PWA) built with Next.js that enables organisations to manage users who can
upload images with quota restrictions. Payments for additional uploads are handled via Razorpay, and images are
stored in AWS S3. Authentication is managed with NextAuth and the UI is built using ShadCN components.

2. Roles & Permissions
Product Owner
 Create, edit, and delete organisations.
 A default Admin user is automatically generated when a new organisation is created.
 Does NOT manage users directly inside organisations.
Admin
 Created automatically when a new organisation is set up.
 Can add, edit, and delete users within their specific organisation.
 Manages user membership and permissions at the organisation level.
User
 Belongs to a specific organisation managed by an Admin.
 Can upload up to 5 images for free.
 To upload more images, must purchase additional slots in multiples of 5 (■100 per set).
 Payment handled via Razorpay.
 Can view all images uploaded by other users within the same organisation.
 Can tag other users while uploading images — tagged user gets a direct notification; no tag → all users in the
org receive a broadcast notification.

5. End-to-End User Flow
 1
Product Owner creates an organisation
 2
Default Admin user is auto-generated for the org
 3
Admin adds, edits, or removes users in the org
 4
User logs in and can upload up to 5 images for free
 5
Beyond 5 images → Razorpay payment required (■100 per 5 slots)
 6
Payment success → quota increased by 5; images stored in AWS S3
 7
If image is tagged → direct notification to tagged user only
 8
If no tag → broadcast notification to all users in the org
 9
All users in the org can browse the shared image gallery

7. Testing Strategy
Frontend Tests (Jest + React Testing Library)

Login form renders correctly and shows validation errors on bad input.

Role-based redirect logic routes users to the correct dashboard.

Image upload component respects quota and shows correct error when exceeded.

Razorpay payment button triggers the checkout flow.

Notification badge updates on new notification arrival.

Gallery filter by tag returns correct subset of images.
Backend Tests (Jest)

POST /api/organisations — creates org and default Admin; validates required fields.

POST /api/users — Admin can add users; rejects duplicate email; enforces role.

POST /api/images — blocks upload when quota exhausted; increments used_quota on success.

POST /api/payments/verify — rejects tampered webhook signature; updates quota on success.

GET /api/notifications — returns only notifications relevant to the calling user.

Auth middleware — returns 401 for unauthenticated requests; 403 for wrong role.
■ Aim for >80% test coverage on business-critical paths: quota logic, payment webhook verification, and
role-based access control.
